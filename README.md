# A-SPECS website

Static website for A-SPECS, a dealer in pre-owned luxury, sports and exotic automobiles.
Plain HTML, CSS and JavaScript, generated by a small Node script. The browser downloads no framework: the [Motion](https://motion.dev) animation library (formerly Framer Motion) is bundled at build time with esbuild, and only the functions used are shipped.

## Quick start

```bash
npm install        # once: installs Motion and esbuild (build-time only)
npm run dev        # build with labelled DEMO cars and serve at http://localhost:4321
npm run build      # production build into dist/ (real data only)
npm run preview    # production build served at http://localhost:4322
npm run check      # production build that exits non-zero while launch blockers remain
```

Requires Node 18 or newer.

## How it works

| Path | Purpose |
| --- | --- |
| `src/config.json` | Business details, domain, form endpoint, hero image. **Anything `null` is hidden on the site.** |
| `src/data/vehicles.json` | Real inventory. Starts empty; the site then shows a designed empty state. |
| `src/data/vehicles.demo.json` | Sample cars for development only (`--demo`). Marked DEMO, `noindex`, no structured data, never used in production builds. |
| `src/assets/` | `styles.css`, `boot.js` (early flags and page-transition hooks), `main.js` (menu, gallery, forms), `inventory.js` (search, filters, sort, layout animation). |
| `src/motion/index.js` | All animation, written against Motion. Bundled to `dist/assets/motion.js`. |
| `src/static/` | Copied to the site root: favicon, icons, social preview image, vehicle photos. |
| `scripts/build.mjs` | Generates every page, `sitemap.xml`, `robots.txt`, `_headers`, and runs QA checks. |
| `scripts/serve.mjs` | Local static server that mirrors clean URLs and applies `_headers`. |
| `scripts/render-images.mjs` | Regenerates `og-image.png` (needs Edge or Chrome) and the PNG icons. |

Pages: Home, Collection (`/inventory/`), one page per car (`/inventory/<slug>/`), About, Sell your car, Contact, Privacy policy, Terms and conditions, 404.

Every build checks for: exactly one `<h1>` per page, alt text on every image, broken internal links, valid JSON-LD, no em dashes in copy, and no inline styles (they would break the Content Security Policy). It then lists the launch blockers that remain.

## Adding a car

Add an object to `src/data/vehicles.json`:

```json
{
  "id": "as-0001",
  "slug": "porsche-911-carrera-s-2021-white",
  "featured": true,
  "status": "available",
  "make": "Porsche",
  "model": "911",
  "variant": "Carrera S",
  "category": "sports",
  "bodyType": "Coupe",
  "year": 2021,
  "registrationYear": 2021,
  "registrationState": "Karnataka (KA)",
  "km": 14200,
  "fuel": "Petrol",
  "transmission": "Automatic",
  "owners": 1,
  "price": 17500000,
  "engine": { "description": "3.0 litre twin-turbocharged flat-six", "powerBhp": 444, "torqueNm": 530 },
  "drivetrain": "Rear-wheel drive",
  "exteriorColour": "Carrara White Metallic",
  "interior": "Black leather, sports seats",
  "features": ["Sport Chrono package", "Sports exhaust"],
  "condition": null,
  "documentation": null,
  "description": "Optional short paragraph about this specific car.",
  "listedOn": "2026-11-09",
  "images": [
    { "src": "/vehicles/porsche-911-carrera-s-2021-white/1.webp", "alt": "White Porsche 911 Carrera S, front three-quarter view" }
  ]
}
```

- **Required:** `slug`, `make`, `model`, `year`, `km`, `fuel`, `transmission`, `category`, `bodyType`, `status`, `listedOn`, and at least one image with `alt` text. The build stops with a clear message if any are missing.
- `status`: `available`, `reserved` or `sold`. Sold cars sink to the end, are hidden unless the visitor ticks "Include sold cars", and lose their enquiry form and price offer.
- `category`: one of `luxury-sedan`, `luxury-suv`, `sports`, `performance`, `supercar`, `exotic`.
- `price`: a whole number in rupees, or `null` to show "Price on request". Only confirmed prices go here; they also appear in structured data.
- `condition` and `documentation`: leave as `null` unless verified. Rows that are `null` are not shown.
- `featured: true` puts the car on the homepage (up to three; otherwise the newest three).
- **Photos:** put them in `src/static/vehicles/<slug>/`. Use WebP, 2000 px on the long edge, about 200 to 400 KB each, all in **16:10** so cards line up. Photograph the actual car. The first image is the card and gallery cover.

Filters (category, body type, fuel, transmission, year) build their options from the cars in the data, so only relevant choices appear.

## Config fields (`src/config.json`)

| Field | Notes |
| --- | --- |
| `siteUrl` | Production origin, for example `https://www.a-specs.in`. Until set: no canonicals, no sitemap, `noindex` on every page, and `robots.txt` disallows crawling. |
| `legalName` | Registered business name, used in the footer and legal pages. |
| `contact.phone`, `contact.whatsapp` | International format, for example `+91 98xxx xxxxx`. WhatsApp buttons (with the car name prefilled) appear only when `whatsapp` is set. |
| `contact.email`, `address`, `city`, `hours` | Shown on Contact and in the footer when present. |
| `contact.mapsUrl`, `contact.mapsEmbedUrl` | Google Maps link and embed URL. The embed is allowed in the CSP only when set. |
| `social.instagram` | Official A-SPECS account URL only. |
| `forms.endpoint`, `forms.accessKey` | See below. |
| `services.sellYourCar` | `false` removes the Sell your car page, navigation and copy. |
| `heroImage` | Homepage image. Replace with A-SPECS's own photography when available. |

## Connecting the forms

Forms post `multipart/form-data` with `Accept: application/json` to `forms.endpoint`. They show success only when the service returns a 2xx response. Without an endpoint, they say plainly that the message was **not** sent.

- **Formspree:** create a form, set `endpoint` to `https://formspree.io/f/<id>`. Leave `accessKey` empty. File uploads need a paid plan.
- **Web3Forms:** set `endpoint` to `https://api.web3forms.com/submit` and `accessKey` to your access key. This key is meant to be public.

The build adds the endpoint's origin to the CSP `connect-src` and `form-action` automatically. Spam protection: a hidden honeypot field, a minimum time to submit, and the provider's own filtering. Turn on the provider's reCAPTCHA or hCaptcha if spam gets through. That needs the provider's script domain added to the CSP in `scripts/build.mjs`.

## Deploying

The build output is `dist/`. Any static host works.

- **Netlify or Cloudflare Pages:** build command `npm run build`, output directory `dist`. Both read `dist/_headers`, which sets CSP, HSTS, nosniff, frame and referrer policy, permissions policy and asset caching. Both serve `404.html` automatically.
- **Vercel:** output directory `dist`. Copy the headers from `dist/_headers` into a `vercel.json` `headers` block.

### Domain and launch checklist

1. Register the domain and add it to the host. Point DNS as the host instructs (usually an `A`/`ALIAS` record for the apex and a `CNAME` for `www`).
2. Wait for the host to issue the TLS certificate. Turn on "force HTTPS" and redirect one of apex or `www` to the other.
3. Set `siteUrl` to the final origin, redeploy, and check that `/robots.txt` allows crawling and `/sitemap.xml` lists every page.
4. Verify the domain in Google Search Console, submit the sitemap, and check a car page with the Rich Results Test.
5. Submit each form once on the live site and confirm the message arrives.
6. Run PageSpeed Insights on the homepage and on one car page, on mobile.

`npm run check` fails until the domain, form endpoint and at least one contact method are set.

## Motion

All animation lives in `src/motion/index.js` and uses [Motion](https://motion.dev) 14.6.0, the library formerly called Framer Motion, through its plain-JavaScript API (`animate`, `scroll`, `inView`, `stagger`, `press`). The build bundles it with esbuild into `dist/assets/motion.js`, about 31 KB gzipped, loaded with `defer`. Versions are pinned in `package.json`.

| Where | What moves |
| --- | --- |
| Hero | The photo settles from a zoom and the headline rises word by word, followed by the text, buttons and category links. While you scroll away, the photo drifts and the copy lifts and fades (scroll-linked). |
| Category marquee | A band of category names loops continuously, speeds up when you scroll, then eases back. |
| Headings | Section headings rise word by word as they enter view. |
| Sections | Blocks fade up, and lists, cards, steps and spec rows stagger in. Kicker rules and category row rules draw across. |
| Tachometer | An SVG gauge on the homepage draws its dial and redline, then the needle sweeps up and settles at idle. It revs again on hover. |
| Vehicle cards | Spring-driven 3D tilt with the photo drifting the other way for depth, plus a circle that grows from the cursor to reveal a light copy of the details (ported from `tilt-card.zip`). |
| Collection | Cards deal in on load. When filters or sort order change, cards glide to their new positions on a spring (FLIP layout animation). |
| Page transitions | Pages crossfade between each other. Opening a car morphs its card photo into the gallery photo on the car's page (cross-document View Transitions, handled in `boot.js`). Browsers without support simply navigate normally. |
| Other | A gold scroll progress line, a header that hides on scroll down, button press springs, staggered mobile menu links, a photo shimmer then fade-in, and a gallery crossfade. |

**Safeguards**
- Cursor effects run only on mouse or trackpad devices.
- With "reduce motion" turned on in the operating system, nothing animates and nothing waits to appear.
- Starting states apply only when `boot.js` has run. If the motion script fails, `boot.js` removes them after 3 seconds, so content is never left hidden.
- Hovering a card preloads its page's main photo, which speeds up navigation and gives the transition a real image to morph.

**Tuning**
- Tilt angle and springs: `MAX`, `SPRING_TILT` and `SPRING_SOFT` in `src/motion/index.js`.
- Marquee speed: `duration`.
- Circle size: `.card__invert` in `styles.css`.
